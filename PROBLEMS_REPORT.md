## Findings from code audit

- **P-04 container flags:** `buildProjectHostConfig()` in `backend/src/services/docker-manager.ts` sets `Privileged: false`, `SecurityOpt: ['no-new-privileges:true']`, and `PidsLimit` default 512 via `WSD_PROJECT_PIDS_LIMIT` (accepted range 64–4096). `Binds` contains only the workspace mapping; no `/var/run/docker.sock` bind is passed and existing CPU/RAM limits are preserved. There is no blanket `CapDrop: ['ALL']`. The socket-proxy overlay is opt-in and off in base compose.
- **P-08 key source:** `backend/src/services/secret-box.ts` writes `v2:<iv>:<authTag>:<ciphertext>:<last4>` with a fresh 12-byte random IV and a verified 16-byte auth tag on every seal. The current key is a dedicated random 32-byte key in `data/enc.key` (0600) or a validated `WSD_ENC_KEY` of 16–1024 non-blank characters; it is never derived from `JWT_SECRET`. `enc1:` blobs remain readable only as migration input using the legacy derivation with `data/crypto.salt`.
- Other verified findings: setup token, explicit trusted-proxy allowlist, runtime opencode major resolver and fail-closed code-server digest checks were implemented where the source confirmed the hypothesis. No source, test or tooling file was changed to produce this report.
