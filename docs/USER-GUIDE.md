## البدء السريع

### إنشاء الحساب

1. افتح اللوحة على `http://localhost:3000`
2. سترى شاشة **إنشاء الحساب** — أدخل اسم مستخدم وكلمة مرور
3. هذا الحساب الوحيد في النظام — كلمة المرور هي التي تحمي كل العمليات الحساسة

### إضافة مزوّد LLM

1. من الشريط الجانبي افتح **Providers**
2. اضغط **+** لإضافة مزوّد
3. أدخل الاسم والعنوان (host) والمفتاح
4. اضغط **Check** للتحقق من الاتصال
5. نجاح التحقق = يمكنك استخدام AI في المشاريع

> يكفي مزوّد واحد لتشغيل كل ميزات AI.

### إنشاء أول مشروع

1. من الشريط الجانبي افتح **Projects**
2. اضغط **Create Project**
3. أدخل الاسم (يُولّد slug تلقائيًا) ومنافذ اختيارية (مثل `8080`)
4. اضغط **Create** — الحاوية تُنشأ وتبدأ بالعمل

## المشاريع

### إنشاء مشروع

- **الاسم**: أي اسم عربي أو إنجليزي (يُولّد slug آليًا مثل `my-project`)
- **الصورة**: اختيارية — صورة Docker مخصصة (الافتراضي: `wsd/workspace`)
- **المنافذ**: اكتب أرقام مفصولة بفواصل مثل `8080,3001,8081` — هذه المنافذ تُنشر للخارج

### إدارة الحاوية

| الفعل | الزر | ملاحظات |
|-------|------|---------|
| تشغيل | **Start** | يشغّل الحاوية `sleep infinity` |
| إيقاف | **Stop** | يوقف الحاوية — الملفات تبقى |
| إعادة بناء | **Recreate** | يحذف الحاوية القديمة ويُنشئ جديدة (لتطبيق تغييرات المنافذ/الموارد) |
| حذف | **Delete** | يحذف الحاوية + الملفات + كل البيانات |

### نشر الملفات

1. داخل صفحة المشروع افتح تبويب **Files**
2. اضغط **Upload** واختر الملفات
3. الملفات تظهر في `workspaces/<slug>/`

### المتغيرات البيئية

من صفحة المشروع → تبويب **Env**:
- أضف متغيرات بتنسيق `KEY=VALUE`
- المتغيرات تُحمّل عند تشغيل الحاوية التالية

### حدود الموارد (CPU / RAM)

من صفحة المشروع → قسم **Resource Limits**:
- **CPU**: رقم صحيح (مثل `2`) أو بالميلي (مثل `500m`)
- **Memory**: بتنسيق binary (مثل `128Mi` أو `1Gi`)
- **ملاحظة**: التغييرات تُطبّق عند إعادة بناء الحاوية فقط (Recreate)

### المنافذ المنشورة

من صفحة المشروع → قسم **Published Ports**:
- أدخل الأرقام مفصولة بفواصل
- منافذ محجوزة لا يمكن استخدامها: `3000` (اللوحة)، `8100` (المحرر)، `4096` (OpenCode)
- تغيير المنافذ يتطلب Recreate

### النشاط

من صفحة المشروع → تبويب **Activity**: يعرض سجل كل ما حدث في المشروع — من أنشأه، متى شُغّل، ما التغييرات التي أُجريت.

## المحرر والطرفية

### المحرر المدمج (VS Code)

1. من الشريط الجانبي اضغط **VS Code**
2. يفتح code-server في iframe مدمج
3. المحرر مُشغّل بدون كلمة مرور (`--auth none`)
4. ملفات كل المشاريع مرئية من `workspaces/`

### الطرفية

1. داخل صفحة المشروع افتح تبويب **Terminal**
2. طرفية xterm.js مربوطة بالحاوية مباشرة
3. **أوضاع**: تبويبات متعددة، وضع المشروع/التحكم، سجل أوامر، تكبير/تصغير

## دردشة AI

### فتح المحادثة

1. داخل صفحة المشروع افتح تبويب **AI Chat**
2. اكتب سؤالك أو طلبك
3. الرد يتدفق مباشرة (streaming)

### الميزات

- **سياق تلقائي**: المحادثة تعرف بنية المشروع وملفاته — لا تحتاج لشرح السياق
- **مرفقات**: يمكنك إرفاق صور أو ملفات نصية مع سؤالك
- **جلسات**: كل محادثة محفوظة — يمكنك العودة لها لاحقًا
- **إيقاف**: زر **Stop** لإيقاف الرد أثناء التدفق
- **عرض الكود**: أكواد Claude/GPT تظهر بألوان مميزة مع زر نسخ

## لوحة التخطيط البصرية

### من صفحة المشروع

1. داخل صفحة المشروع افتح تبويب **Canvas**
2. لوحة بيضاء فارغة — أضف ملاحظات لاصقة وبطاقات مهام
3. اسحب وأفلت لإعادة الترتيب

### من صفحة Planner

- من الشريط الجانبي افتح **Planner**
- ترى بطاقات كل المشاريع مع حالة اللوحة وآخر تعديل
- انقر على بطاقة مشروع → يفتح مباشرة على تبويب Canvas

> لوحة التخطيط تُمرَّر كسياق AI تلقائيًا — وكلاء AI يقرأون خططك عند إنتاج الخطط.

## الدردشة الجماعية

### الصفحة الرئيسية

من الشريط الجانبي افتح **Chat** — صفحة دردشة الفريق.

### القنوات

| النوع | الوصف |
|-------|-------|
| قنوات جماعية | تُنشأ بأي اسم — للنقاش العام أو مواضيع محددة |
| محادثات مباشرة | `dm:<user1>:<user2>` — تلقائية عند النقر على اسم مستخدم |
| قنوات مشاريع | `project:<slug>` — تلقائية لكل مشروع، تُنشأ معه وتموت بحذفه |

### الميزات

- **إرسال رسائل**: اكتب واضغط Enter
- **رد على رسالة**: انقر على أيقونة الرد
- **تثبيت**: ثبّت رسالة مهمة
- **بحث**: ابحث في رسائل القناة بحساسية للحالة
- **مرفقات**: ارفع ملفات حتى 10MB (حتى 5 ملفات)
- **تنبيهات @**: اذكر مستخدمًا بكتابة `@`
- **unread**: مؤشر عدد الرسائل غير المقروءة لكل قناة
- **حضور**: مؤشر من هو متصل حاليًا

## المزوّدون

### إضافة مزوّد

1. من الشريط الجانبي افتح **Providers**
2. اضغط **+**
3. اختر النوع: Ollama / OpenAI / Anthropic / Gemini / Azure
4. أدخل البيانات المطلوبة (Host، Key، Model)
5. اضغط **Verify** للتحقق

### قفل أمان المزوّدين

من **Settings → Providers Security**:
- فعّل القفل لتثبيت كلمة مرور منفصلة على صفحة المزوّدين
- عند التفعيل: لا يمكن إدارة المزوّدين بدون كلمة المرور
- كلمة المرور منفصلة عن كلمة مرور الحساب
- **-auto-relock**: يمكن ضبط مؤقت لقفل تلقائي بعد فترة خمول (5/15/30 دقيقة)

### دعم Azure OpenAI

- النوع: `azure`
- العنوان: `{host}/openai/deployments/{deployment}/chat/completions`
- النموذج = اسم الـ Deployment
- الكشف التلقائي عن عناوين `*.openai.azure.com`

## إدارة الفريق

### إضافة عضو

1. من صفحة المشروع افتح تبويب **Team**
2. اضغط **Add Member**
3. اختر المستخدم والدور

### الأدوار

| الدور | الصلاحيات |
|-------|----------|
| Admin | كل شيء (نقل ملكية، حذف مشروع، إدارة أعضاء) |
| Editor | قراءة + كتابة + تشغيل/إيقاف + تصدير |
| Viewer | قراءة فقط |

### نقل ملكية المشروع

1. افتح تبويب **Team** في المشروع
2. اضغط **Transfer Ownership**
3. أدخل كلمة مرور الحساب للتأكيد (عملية sudo)
4. المالك القديم يبقى عضو Admin

## الإعدادات

### الصفحة الرئيسية (`/settings`)

| القسم | الوصف |
|-------|-------|
| **Profile** | تعديل الاسم المعروض، البريد الإلكتروني، السيرة، صورة المستخدم |
| **Change Password** | تغيير كلمة مرور الحساب |
| **Two-Factor** | تفعيل/تعطيل التحقق بخطوتين (TOTP) — متوافق مع Google Authenticator/Authy/Aegis |
| **Providers Security** | قفل كلمة مرور منفصل على صفحة المزوّدين |
| **Idle Security** | إنهاء تلقائي عند الخمول (off / 30 / 60 / 120 دقيقة) |
| **Logout Everywhere** | إلغاء جميع الجلسات النشطة |
| **Export/Import** | نسخ احتياطي للإعدادات (المفاتيح لا تُصدَّر) |
| **Storage** | جدول مفصل لاستخدام التخزين لكل مشروع |
| **Webhooks** | إدارة نقاط Webhook للتنبيهات |
| **About** | معلومات النظام والإصدار |

### التحقق بخطوتين (2FA)

1. من Settings → Two-Factor
2. اضغط **Setup** — يظهر مفتاح QR
3. امسح الرمز بتطبيق المصادقة
4. أدخل الرمز للتفعيل
5. في تسجيل الدخول: بعد كلمة المرور يُطلب رمز المصادقة

> **في حال فقدان جهاز المصادقة**: أدخل ملف `data/users.json` على الخادم واحذف حقل `totp` ثم أعد تشغيل الخادم.

## النسخ الاحتياطي والاستعادة

### تصدير إعدادات النظام

1. من Settings → Export
2. أدخل كلمة مرور الحساب
3. يُنزَل ملف JSON يحتوي الإعدادات (المفاتيح لا تُصدَّر أبدًا)

### استيراد إعدادات النظام

1. من Settings → Import
2. اختر ملف JSON
3. أدخل كلمة المرور
4. الدمج يتم تلقائيًا — العناصر الموجودة تفوز دائمًا

### تصدير مشروع

1. داخل صفحة المشروع اضغط **Export**
2. يُنزَل ملف `madar-<slug>-<timestamp>.tar.gz`
3. يحتوي: ملفات المشروع + ملاحظات + لوحة التخطيط + بيئة + وصف

### استيراد مشروع

1. من شريط أدوات Projects اضغط **Restore**
2. اختر ملف التصدير
3. يُنشأ مشروع جديد بالملفات المستوردة

### نسخ احتياطي مجدول

1. داخل صفحة المشروع → تبويب **Snapshots**
2. فعّل الجدولة واختر التكرار (1h, 3h, 6h, 12h, 24h, 7d)
3. حدد عدد النسخ المحفوظة (حتى 20)
4. يمكنك القبض يدويًا بأمر **Capture Now**

## استكشاف الأخطاء

### أسئلة شائعة

| المشكلة | الحل |
|---------|------|
| لا أستطيع تسجيل الدخول | تحقق من `JWT_SECRET` في `.env` — يجب أن يكون مولّدًا |
| إنشاء المشروع يفشل | تأكد أن `WSD_WORKSPACES_HOST_DIR` مسار مطلق صحيح |
| المحرر لا يفتح | تأكد أن المنفذ `8100` متاح وحاوية `app` تعمل |
| AI لا يرد | تحقق من صفحة Providers — اضغط Check بجانب المزوّد |
| ذاكرة عالية | حدّد حدود RAM من صفحة المشروع → Resource Limits |
| سلة المحذوفات فارغة | المحذوفات تُحذف نهائيًا بعد 7 أيام تلقائيًا |
| نُسيت كلمة المرور | `docker compose down -v` ثم أعد التثبيت (سيتم حذف جميع الإعدادات) |
| ملفات المشروع لا تظهر داخل حاويته | تأكد أن `WSD_WORKSPACES_HOST_DIR` هو مسار المضيف الفعلي المطلق وليس مسارًا داخل الحاوية |
| حدود الموارد لا تُطبَّق | حدود CPU/RAM تتطلب Recreate — اضغط "Recreate container" من صفحة المشروع |

### سجل أمني

من Settings → Security Activity — يعرض آخر 50 حدث أمني:
- تسجيلات دخول ناجحة/فاشلة
- تغييرات كلمة المرور
- قفل/فتح المزوّدين
- تصدير/استيراد الإعدادات

### أوامر مفيدة

```bash
# فحص حالة الحزمة
docker compose ps

# متابعة السجلات
docker compose logs -f app

# فحص سجلات مشروعي
docker compose logs -f app | grep <slug>

# إعادة تشغيل
docker compose restart app
```

## ملاحظات مهمة

- حاويات المشاريع تبدأ بـ `sleep infinity` — يجب تشغيل الخادم يدويًا من الطرفية
- لا يوجد متصفح داخل الحاوية — معاينات المشاريع تُفتح في متصفحك الخارجي
- ملفات المشاريع محفوظة في `./workspaces/` والإعدادات في volume باسم `wsd-data`
- كلاهما يبقى بعد إعادة التشغيل وإعادة البناء
- الإصدار الحالي: **BETA**
